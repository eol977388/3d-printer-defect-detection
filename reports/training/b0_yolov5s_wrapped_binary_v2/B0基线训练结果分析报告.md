# B0 基线训练结果分析报告

> 阅读版式：正文按 18 px 显示；图片缩小为页面宽度的约 65%，最大宽度 760 px。若某些 Markdown 阅读器屏蔽上面的样式，图片本身仍通过 HTML 宽度属性限制为 65%。

## 1. 结论摘要

本次 B0 基线训练已正常完成 50 个 epoch，模型收敛充分，训练过程未见明显发散或典型过拟合。按 YOLOv5 v7.0 的默认最佳权重评价规则，最佳结果出现在 CSV 记录的 `epoch=47`，即人们通常所说的**第 48 轮**：Precision 为 0.99480，Recall 为 0.99584，mAP@0.5 为 0.99353，mAP@0.5:0.95 为 0.94294。

模型在当前 clean_v2 验证集上的表现很好，但这仍是**验证集结果**，不能直接等同于工业现场泛化能力。验证批次图中可以看到较多连续工况、相似背景和相近构图；虽然数据清洗阶段已按相似簇整体划分来避免跨集合泄漏，后续实验选择阶段仍只能使用 train/val。模型、增强、超参数和部署阈值全部确定并冻结后，才使用从未参与训练与调参的 test 集进行一次最终评估，并增加新时间、新批次、新光照和新打印材料的数据进行外部检验。

## 3. 核心结果

YOLOv5 采用以下 fitness 选择 `best.pt`：

`fitness = 0.1 × mAP@0.5 + 0.9 × mAP@0.5:0.95`

| 结果 | Precision | Recall | mAP@0.5 | mAP@0.5:0.95 | fitness |
|---|---:|---:|---:|---:|---:|
| 最佳轮次：第 48 轮（epoch=47） | 0.99480 | 0.99584 | 0.99353 | 0.94294 | 0.947999 |
| 最后一轮：第 50 轮（epoch=49） | 0.99475 | 0.99582 | 0.99349 | 0.94194 | 0.947095 |

最佳轮次与最后一轮非常接近，说明后期训练已进入稳定平台。正式验证、test 测试和后续推理应优先使用 `weights/best.pt`；`weights/last.pt` 主要用于继续训练或对照。

这张图不是模型精度图，而是训练标签中每个框的 4 个归一化参数之间的关系图：`x` 是框中心的左右位置，`y` 是框中心的上下位置，`width` 是框宽，`height` 是框高，数值都除以了原图宽高，所以范围是 0～1。

- 对角线上的 4 个小图：分别看 `x、y、width、height` 自己的数量分布。峰越集中，说明该参数越固定。例如 `x、y` 集中，表示喷嘴和目标通常出现在相似位置。

- 点带呈右下方向：两个参数负相关；接近圆形散点则表示关系较弱。

本图中 `x、y` 和框尺寸都有较明显的集中或成团现象，说明相机位置、喷嘴位置和目标尺度相对固定。这有利于模型快速学习，但也意味着模型可能习惯当前构图。因此外部验证应主动加入喷嘴位置偏移、拍摄距离改变、小型/大型裹头以及不同相机角度。该图主要用于发现数据偏置，不用于评价模型好坏。

### 图 13：混淆矩阵（confusion_matrix.png）

<img src="confusion_matrix.png" alt="混淆矩阵" width="65%">

本项目仍然是二分类，`background` 不是第三个训练类别，也不在数据集 `names` 中。目标检测除了判断类别，还必须判断“有没有检测框与真实框匹配”，因此 YOLOv5 在混淆矩阵外加 background 行/列来记录漏检和误检：

- 最下面的 `background` 行：真实目标存在，但没有预测框成功匹配，是漏检（FN）。
- 最右侧的 `background` 列：模型给出了预测框，但没有真实框与它成功匹配，是误检（FP）。
- 中间 2×2 区域：才是两个真实类别之间的正确识别或互相错分。

坐标轴应按图上的标签读取：横轴是 True（真实类别），纵轴是 Predicted（预测类别）。矩阵已经归一化，`nozzle_wrapped` 正确识别约 0.99，`nozzle_not_wrapped` 约 1.00；图中主要剩余问题是极少量 wrapped 落入 background，即未检出，两个真实类别互相误判几乎没有。该图使用 YOLOv5 混淆矩阵的默认判断条件，通常为置信度 0.25、匹配 IoU 0.45，不能直接当作部署 `conf=0.7` 时的混淆矩阵。

### 图 14：PR 曲线（PR_curve.png）

<img src="PR_curve.png" alt="PR 曲线" width="65%">

这是使用训练结束后选出的 `best.pt` 在**完整 val 集**上的预测结果绘制的 PR 曲线，不是 train 集曲线，也不是单张图片的曲线。验证时先以很低的 `conf=0.001` 保留候选预测并执行 NMS，然后在统计阶段从高到低遍历预测置信度，相当于尝试许多不同的置信度阈值；在 IoU=0.5 的正确匹配标准下，分别计算每个阈值对应的 Precision 和 Recall，连接起来就是一条 PR 曲线。

其中 Precision 表示保留下来的检测中有多少是真的，Recall 表示真实目标中有多少被找到了。曲线横轴为 Recall、纵轴为 Precision；曲线越靠近右上角、下面积越大越好。曲线下面积就是 AP@0.5。`nozzle_wrapped` 的 AP@0.5 为 0.994，`nozzle_not_wrapped` 为 0.993，总体 mAP@0.5 约 0.994。这里的曲线反映 val 集上阈值变化的总体表现，不代表某一个固定部署阈值。

### 图 15：F1—置信度曲线（F1_curve.png）

<img src="F1_curve.png" alt="F1—置信度曲线" width="65%">

F1 是 Precision 与 Recall 的调和平均。横轴的 confidence 是模型在 **val 集预测框上输出的类别置信度阈值**，不是训练学习率、不是训练损失，也不是训练阶段固定使用的一个置信度。验证统计把阈值从 0 扫描到 1：只保留 `预测置信度 ≥ 当前阈值` 的框，再重新计算指标。图中自动标注的全类别最优点约为 `F1=1.00、conf=0.115`（显示值经过四舍五入）。这只是当前 val 集上 Precision 与 Recall 最均衡的参考点，不是工业部署阈值的唯一依据；裹头漏检代价高时，应优先确保 Recall，再结合误报成本选择阈值。

### 图 16：Precision—置信度曲线（P_curve.png）

<img src="P_curve.png" alt="Precision—置信度曲线" width="65%">

阈值较低时，模型保留的框多，其中可能混入更多误检；阈值提高后，低置信度误检先被过滤，因此 Precision 通常上升。图中 `conf=1.000` 时 Precision 显示为 1.00，只代表剩下的极少数最高置信预测没有误报，并不意味着应把部署阈值设为 1.0；阈值过高会同时过滤真目标并造成漏检。

### 图 17：Recall—置信度曲线（R_curve.png）

<img src="R_curve.png" alt="Recall—置信度曲线" width="65%">

阈值较低时，大多数真目标预测都能保留，所以 Recall 较高；阈值升高后，一部分置信度不够高但实际正确的框也被过滤，因此 Recall 下降。`nozzle_wrapped` 在高阈值区域比 `nozzle_not_wrapped` 更早下降，因此部署使用 `conf=0.7` 前必须单独验证 wrapped 类的漏检率。当前曲线看，0.7 附近仍处于较高 Recall 区域，但应以 test 集精确统计为准。

图 15～图 17 使用的是同一套 best.pt 对 val 集的预测，只是纵轴分别换成 F1、Precision 和 Recall。其共同规律是：提高阈值通常会减少误检、提高 Precision，却可能增加漏检、降低 Recall；F1 用来寻找两者的折中点。工业裹头检测中漏检通常比误报更危险，所以阈值不应只按最高 F1 机械决定，而应结合 test 集漏检成本和现场报警策略确定。

## 7. 下一步建议

1. 目前不要评估 test 集。先将本次 B0 的配置、val 指标和权重哈希固化，后续增强、模型和超参数实验统一只根据 val 集选择。
2. 保留 B0 的标准增强，再增加一个只改变增强开关的消融实验，例如 B1-noaug；其余网络、预训练权重、数据划分、epoch、batch、seed 和评价方式必须与 B0 相同。
3. 根据 val 结果确定最终训练方案，并在 val 集上完成 `conf=0.7` 的合理性检查；不得根据 test 结果反复修改方案或阈值。
4. 模型结构、增强、超参数和部署阈值全部确定后，锁定对应的 `best.pt`，再对冻结的 test 集做一次最终评估，统计两类 Precision、Recall、mAP、混淆矩阵和逐图错误，尤其关注 wrapped 漏检。
5. 补充独立的新时间、新材料、新光照或新设备数据作为外部验证，检验模型是否依赖固定背景与连续帧特征。

## 8. 关于标准增强基线与无增强消融

本次 B0 使用的 `hyp.scratch-low.yaml` 中 Mosaic、HSV、平移、缩放和左右翻转，属于 YOLOv5 v7.0 官方标准低增强配置，因此 B0 的含义是“标准 YOLOv5s 训练基线”，不是“零增强基线”。基线的作用是提供公认、可复现的参照方案，并不要求关闭所有增强。

若要回答“数据增强是否有效”，应增加一个无增强或分组消融实验，而不是修改已经完成的 B0：

- B0-standard-aug：保留本次官方标准增强。
- B1-noaug：关闭 Mosaic、HSV、平移、缩放和翻转，其余配置与 B0 完全相同。
